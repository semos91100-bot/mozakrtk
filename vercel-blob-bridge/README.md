# جسر Vercel Blob لموقع مُذاكرة

هذا المجلد تطبيق Node.js صغير يُنشر كـ Vercel Function. يوفّر واجهة خاصة ومحدودة لملفات JSON الثلاثة التي يحتاجها الموقع، ويستخدم حزمة Vercel الرسمية `@vercel/blob`. لا يُرسل المتصفح أي رمز تخزين.

> Vercel Blob تخزين كائنات/ملفات، وليس قاعدة بيانات علائقية. بيانات الحسابات والمحتوى والدعم تحفظ كملفات JSON خاصة. إذا كنت تحتاج استعلامات علائقية ومعاملات متزامنة، استخدم قاعدة بيانات مثل Postgres بدل Blob.

## النشر

1. أنشئ مشروعًا جديدًا على Vercel واجعل **Root Directory** هو `vercel-blob-bridge`.
2. في مشروع Vercel، أنشئ **Blob Store خاصًا (Private)** واربطه بالمشروع. سيضيف Vercel متغيرات المصادقة اللازمة، ومنها `BLOB_READ_WRITE_TOKEN` أو اعتماد OIDC مع `BLOB_STORE_ID`.
3. أنشئ قيمة سرية طويلة عشوائية (مثل ناتج `openssl rand -hex 32`) وأضفها إلى **Project Settings → Environment Variables** باسم `BLOB_BRIDGE_SECRET`. لا تضعها في Git أو داخل ملفات الموقع.
4. ثبّت Vercel CLI محليًا أو استخدم ربط Git ثم انشر هذا المجلد إلى Vercel. هذا المجلد هو خدمة منفصلة؛ لا تغيّر استضافة واجهة PHP بسببها.
5. انسخ رابط نشر الخدمة، مثل `https://اسم-الخدمة.vercel.app`.

## إعداد استضافة PHP

أضف المتغيرين التاليين في لوحة استضافة PHP (Server Environment Variables)، مستخدمًا نفس قيمة السر في الطرفين:

- `BLOB_BRIDGE_URL=https://اسم-الخدمة.vercel.app`
- `BLOB_BRIDGE_SECRET=نفس_السر_المحفوظ_على_Vercel`

تأكد أن PHP 8+ وإضافة cURL مفعّلتان وأن الخادم يستطيع الاتصال عبر HTTPS. لا تحفظ قيمة السر في `assets/*.js` أو مستودع عام.

## البيانات ونقل البيانات الموجودة

يقرأ الـPHP مفاتيح `users.json` و`content.json` و`support.json` من Blob عند تفعيل الإعدادين أعلاه. عند أول قراءة لملف غير موجود في Blob، ينسخ نسخة JSON الموجودة محليًا (إن وُجدت) إلى Blob تلقائيًا؛ وبذلك تنتقل بيانات المحتوى الابتدائية وملفات JSON الموجودة دون حذف محلي. إذا غاب أحد المتغيرين، يستمر المشروع في استخدام `api/storage` المحلي. إذا تم ضبط أحدهما دون الآخر، يرفض الـAPI العمل بدل الرجوع الصامت إلى تخزين قد يؤدي لتشتت البيانات.

يجب إبقاء Blob Store خاصًا؛ البيانات تتضمن معلومات حسابات وبصمات كلمات مرور. لا تضع بيانات اعتماد Vercel داخل الموقع أو ملف ZIP. احتفظ بنسخة احتياطية قبل تحويل موقع منشور، واختبر التسجيل والدخول وحفظ التقدم ولوحة الإدارة بعد النشر.

**ملاحظة مهمة للتزامن:** ملفات JSON تُقرأ وتُكتب كملف كامل، لذلك هذا الأسلوب مناسب لموقع صغير وحركة كتابة محدودة. إذا عدّل مستخدمان البيانات نفسها في اللحظة ذاتها فقد يتغلب آخر حفظ على الأول؛ Blob لا يوفر معاملات قاعدة بيانات. للإنتاج ذي الاستخدام المتزامن أو البيانات الحساسة الحرجة، انقل سجلات الحسابات والدعم إلى قاعدة بيانات فعلية، واستخدم Blob للملفات فقط.
